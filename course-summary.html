1. What the module is about

Big idea: top models are nearly always right but expensive and rationed. Cheap models make more mistakes. The module teaches two skills:

  1. Routing: send each request to the cheapest model that can still handle it, using an automatic rule.
  2. Quorum (k-of-n vote): when an answer carries consequences, ask several models, keep the answer only if a strict majority agrees, and abstain otherwise. Then check the result independently.

SQL conventions (binding for you and for the models)

  • Revenue = SUM(quantity_product * price), integer euro cents excl. VAT. Output is one row with one column named revenue_cents.
  • A period includes its start and excludes its end: date >= start AND date < end.
  • Age means completed age, computed with month and day, never as a plain difference of years. "On reference date X" is a different question from "at the time of the order".
  • Return 0, not NULL when nothing matches (use COALESCE(SUM(...),0)).

Batch rules

  • Base batch: 100 cells (60 Groq + 40 OpenRouter), 20 per operator. Access checks and retries are counted separately. Aim to keep a margin of 5 extra calls per operator.
  • One request in flight per sub-group, at least 3 s between requests, temperature 0, output capped at 1024 tokens, 45 s timeout.
  • At most 1 retry per cell (2 attempts across runs), only for 429 with Retry-After ≤ 60 s, a timeout, or a 5xx error. Errors 400–404 are recorded and not retried.
  • Changing the prompt or the reference starts a new experiment: use new --state/--out files and keep the old ones.
  • Each check_access.py run costs 3 Groq + 2 OpenRouter calls. A new API key does not add capacity.
  • TD 2 and TD 3 need no new network calls: they work on the saved traces.
  • If access fails, the instructor supplies traces-reelles.jsonl and you run --replay. Replay lines are labelled nature=replay and lose no points.

Cost formula (TD 3)

API-equivalent (USD excl. tax) = (input_tokens × in_price + output_tokens × out_price) / 1,000,000
e.g. gpt-oss-120b, 2,000 in / 300 out → (2000×0.15 + 300×0.60)/1e6 = 0.00048 USD
Annual: 20 people × 10 req/day × 20 days × 12 months = 48,000 requests
A check is worth it when: check cost per question < error cost × error frequency
